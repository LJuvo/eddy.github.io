第0章 移动端业务场景与角色分析

本章从业务场景出发，明确巡护APP的使用者、工作环境与典型故事，为后续设计决策提供依据。所有UI/UX选择（按钮大小、配色、离线策略、低功耗方案）均须回溯到本章场景验证。

0.1 角色定义

巡护APP面向三类核心用户，其工作场景、频率和任务差异显著，设计时须兼顾共性与差异化需求。

0.2 野外工作环境特征

保护区自然环境在网络、光线、操作、设备四个维度均对APP设计提出严苛要求。

📡网络条件
核心区：无信号（占巡护时间约40%）
缓冲区：2G/3G弱网（约35%）
实验区/管理站：4G/WiFi（约25%）
设计决策：离线优先（Offline-First）架构，所有核心功能本地SQLite缓存，网络恢复自动增量同步
☀️光线条件
晴天强光：屏幕反光严重，浅色背景看不清
阴天/林间：低光环境
夜间/洞穴：需深色模式+高对比度
设计决策：提供"强光模式"（高对比度深色主题、粗边框、加大字号）；避免浅灰文字；重要状态用色块而非细线
🧤操作条件
单手操作：另一手持工具/攀爬/记录
戴手套：湿手/厚手套触控精度低
雨中：屏幕水迹干扰、设备防水袋
设计决策：触摸目标最小44×44pt、按钮间距≥8pt；主操作按钮全部集中在底部1/3拇指热区；关键操作提供实体按钮级反馈
🔋设备条件
电量有限：单日巡护8h+无充电条件
存储有限：离线地图+照片占用大
防水防摔：三防机性能中低端
设计决策：低功耗模式（降低GPS采样/屏幕亮度）；存储预警+一键清理；矢量瓦片地图；后台任务批量执行

0.3 典型野外场景故事

以下5个场景故事覆盖日常巡护、科考、应急、夜间、同步全链路，作为后续页面设计的验证用例。

场景1：清晨无网轨迹记录
角色：老张（日常巡护员） · 环境：核心区清晨 · 网络：无信号
清晨6:30，老张从管理站出发进入核心区，手机信号已断。他打开巡护APP点击"开始巡护"，APP自动检测网络状态并在顶部显示紫色"离线模式"横幅。轨迹在本地SQLite按10秒间隔记录，GPS点坐标、海拔、速度实时写入本地。行进中他发现一处河岸塌方，在无网情况下拍照（自动叠加GPS水印和时间戳）、选择类型"地质灾害"并输入描述，数据全部进入本地待同步队列。整个上午他的巡护里程5.8km，记录3个观察点，APP耗电仅8%。
场景2：发现大鲵产卵场拍照取证
角色：小李（科考队员） · 环境：缓冲区溪流 · 网络：2G弱网
小李在溪流浅滩发现大鲵产卵场，这是重要科考发现。他打开APP"多媒体取证"，切换到水印相机模式，拍摄12张照片+1段30秒视频+5分钟环境录音。每张照片自动叠加经纬度（精度±3m）、海拔、时间、巡护员姓名、方位角水印。他选择关联物种"大鲵"、标记为"国家二级保护动物"并添加生境描述。2G网络下照片无法实时上传，全部本地缓存，视频自动压缩为720p以节省空间。返回缓冲区边缘时，APP自动开始后台分片上传，不影响他继续记录。
场景3：暴雨中非法捕鱼紧急上报
角色：老张（日常巡护员） · 环境：缓冲区河边暴雨 · 网络：2G极弱
暴雨中老张发现3人在非法电鱼，情况紧急。他掏出手机（套在防水袋中），长按APP图标快捷方式"紧急上报"，APP直接启动紧急上报流程：自动打开摄像头录制视频（带水印）、同时在后台持续上报GPS位置（使用SMS兜底通道如果数据网络失败）。他戴着手套点击大尺寸"紧急上报"红色按钮，事件立即标记为"紧急"级别，本地最高优先级缓存。APP尝试通过2G网络发送关键信息（类型+GPS+1张缩略图），完整视频等网络恢复后上传。PC端指挥中心第一时间收到告警弹窗并派单给最近的执法队。
场景4：夜间可疑船只热成像记录
角色：应急队员老王 · 环境：夜间实验区水面 · 网络：4G
夜间23:00，老王接指挥中心调度，在诺水河下游发现可疑船只可能非法采砂。他携带外接热成像设备到达现场，APP自动切换到"夜间模式"（深色主题+红色调保护夜视能力）。他通过APP连接热成像设备，录制热成像视频，同时用可见光相机拍摄取证。APP实时将位置和视频流回传指挥中心（RTMP低延迟），在地图上标记船只位置和移动方向。执法队到达前，他通过APP接收指挥中心消息（语音播报），全程戴手套单手操作。
场景5：返回管理站WiFi同步数据
角色：老张/小李 · 环境：管理站 · 网络：WiFi
下午17:00老张结束巡护返回管理站，手机自动连接WiFi。APP立即检测到网络恢复，顶部紫色横幅变为蓝色"正在同步..."并显示进度条（12条待同步记录、38张照片）。同步采用断点续传+分片上传，中途他去吃饭回来已完成。同步完成后APP弹出"今日巡护数据已同步至PC端"提示，PC端"巡护记录审核"模块自动出现老张的轨迹和事件记录，值班员开始审核。小李的大鲵记录被标记为"重要发现"自动进入科考数据库。

第1章 移动端设计系统规范

1.1 设计原则

巡护APP面向野外复杂环境，所有设计决策以"野外可用性"为最高准则，以下五大原则贯穿全部页面与组件：

原则一 · 野外可用性优先
所有可交互元素须考虑户外强光可视（高对比度、避免细线条/浅灰文字）、戴手套操作（触控目标≥44×44pt、按钮间距≥8pt）、雨雪天气（避免依赖复杂手势，关键操作提供按钮）。主按钮使用高饱和度生态绿#2D7D46，全宽展示。
原则二 · 离线优先（Offline-First）
核心区无网是常态而非异常。所有核心功能（轨迹记录、拍照取证、异常上报、任务打卡）支持离线：数据先写入本地SQLite，网络恢复后自动增量同步。页面加载优先读取本地缓存，并提供明确的同步状态指示（紫色离线横幅/蓝色同步进度条）。
原则三 · 单手操作优化
巡护员常一手持设备、一手持工具/攀爬。关键操作按钮（开始巡护、拍照、紧急上报）必须位于屏幕下半区（拇指热区）。顶部导航栏仅放置返回按钮和低频操作。FAB浮动按钮固定在右下角。
原则四 · 低功耗优化
野外充电困难。定位策略：巡护中10秒记录一次（静止降频），非巡护仅主动请求时定位。提供"省电模式"自动降亮度+缩短锁屏。地图使用矢量瓦片。后台任务批量执行。电量低于20%时提示关闭高频GPS。
原则五 · 一致性
全APP使用统一组件库、色彩、字体、交互模式。相同功能在不同页面使用相同图标和位置（返回按钮始终左上、主操作始终底部），降低学习成本和误操作。

1.4 尺寸与间距

  • 栅格系统：8pt栅格，所有间距、尺寸为8的倍数（8/12/16/24/32/44/48）。
  • 基准尺寸：375×812pt（iPhone X），适配iPhone 8~iPhone 15 Pro Max及主流Android 1080×2340（密度3）。
  • 安全区适配：顶部状态栏40~44pt、底部Home Indicator 20~34pt、底部Tab栏高64pt（含底部安全区）。所有内容避开刘海和底部指示条。
  • 单手热区：屏幕底部1/3区域（约距底部250pt内）为拇指易达区，主要操作按钮（开始巡护、拍照、FAB）必须置于此区域。屏幕顶部1/4为困难区，仅放返回/关闭等低频操作。
  • 触摸目标：所有可点击元素最小44×44pt（HIG规范），按钮间距≥8pt避免误触。戴手套场景主要按钮加大至48~52pt高。
  • 内容边距：页面左右边距16pt，卡片内边距14pt，列表项高度≥48pt。

2.5 离线模式全局设计

网络状态检测机制

  • 实时检测：使用NWPathMonitor(iOS)/ConnectivityManager(Android)实时监听网络变化，状态切换延迟<1秒。

同步队列指示器

全局维护一个持久化的同步队列（基于Room/CoreData），每个待同步项有：类型、优先级（紧急/高/普通）、状态（等待/上传中/失败）、重试次数、创建时间。同步策略：

  • 网络恢复时：自动按优先级顺序同步，紧急事件优先。
  • WiFi下：自动同步所有内容包括视频。
  • 蜂窝网络：默认仅同步文本和压缩图片，视频询问用户或WiFi下传。
  • 冲突处理：采用"最后写入胜出+冲突日志"策略，冲突项在PC端审核时提示。
  • 失败重试：指数退避重试（1s/2s/4s/8s/16s/30s/60s，最大间隔5分钟），连续失败10次标记为"需手动处理"。

  • 数据沉淀：所有确认记录进入PC端"物种数据库"，累积形成物种分布点图层（可在GIS地图上展示），支撑年度生物多样性评估报告、保护红线调整建议等。
  • 模型迭代：专家确认的新记录（尤其是本地模型误识别的）用于模型再训练，定期通过OTA下发更新的本地模型文件。
核心设计理念总结：v2.0版本以"野外可用·离线优先·单手操作"为核心，围绕巡护员真实野外工作场景构建完整的业务闭环。APP端负责数据采集（野外）、PC端负责数据管理（室内），两端通过同步机制形成有机整体。所有设计决策（大按钮、高对比度、离线缓存、低功耗、水印取证）都可回溯到第0章的野外场景故事验证。
